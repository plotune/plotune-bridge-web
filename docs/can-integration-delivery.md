# Virtual Bridge CAN integration delivery

Run `npm run test:virtual:can` with Node 22+, `uv`, Python 3.13, and Chromium installed. The script starts the reference virtual Bridge and bench services from the sibling Nexus checkout at `/workspace/plotune-nexus/plotune-bridge/plotune-bridge-can`; set `NEXUS_CAN_ROOT` to that package root elsewhere. It serves WebSocket endpoints on loopback ports 19101, 19111, 19121, 19141, 19201/19202, and 19301/19302, then runs the full `playwright.virtual.config.ts` matrix with all seven endpoint variables set. It shuts down every process on exit.

The fixtures use a two-channel Bridge with a seeded 100 Hz stream and TX echo, an independent second Bridge, a fresh unconfigured Bridge, a 4-frame queue at 10 kHz to force device drops, a one-channel synthetic ECU bench, and a second bench endpoint that explicitly allows `https://bridge.plotune.net`. Artifacts are written to `.artifacts/can-integration/`: per-server startup logs and the full Playwright log. Playwright also retains its normal `test-results/` trace and failure context. The artifact directory is intentionally ignored by Git.

The integration scenarios verify both channels and per-channel non-decreasing device timestamps, transmit echo and device counters, replacement-on-connect, two-device stream attribution and TX isolation, device overflow reconciliation, single-channel configuration and reload behavior, synthetic ECU periodic traffic and ISO-TP/UDS/XCP exchanges, and WebSocket origin allow-list behavior. Channel settings are edited through each device's Settings dialog, matching the current workspace UX.

This verifies the local WebSocket simulator contract and client behavior. The simulator and bench are software models; these results do not establish electrical CAN behavior, physical timing or throughput, browser local-network permission prompts, Wi-Fi, WebRTC, or live-hardware support. CAN FD is unsupported in the current Bridge contract and UI: the descriptor reports `can_fd: false`, and FD fields are rejected. This delivery makes no live CAN FD claim.

Traceability scope: BR-WEB-001 rev2 (local behavior only), BR-WEB-002 rev1, BR-WEB-003 rev1, BR-WEB-004 rev2, BR-WEB-006 rev2 (local-origin behavior only), and BWEB-043 rev2 (partial UX). These references are implementation scope only; this simulator run does not close requirements concerning hardware or browser-native permissions.
